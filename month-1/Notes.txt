-----------Pydantic--------
- handles parsing, structural type validation, and data serilaization, In v2, the internals were rewritten in Rus for extreme performance
- BaseModel: define schemas using standard Python type hints.
- @field_validator: built via pydantic.field_validator;must be structured as @classmethod;catches custom formatting rules e.g stripping strings , checking for characters etc before data ever touches your FASTAPI logic
- @computed_field: Dynamic output serilaization, built via pydantic.computed_field;converts standard pythong property methods into JSON key-value pairs during serialization; great for calculating values on the fly without wasting database storage space

-----FastAPI----
- works symbiotically with Pydantic schemas to automate doc and handle data marshaling

Incoming JSON Body ──> [ TodoRequest Schema ] ──> Custom Field Validators ──> Endpoint Logic
                                                                                  │
Outgoing JSON Body <── [ TodoResponse Schema ] <── Computed Fields 💾 <────────────┘

-------------Instructor-----------------
- two critical skills for building applications with LLMs: function-calling and structured data extraction.
-Function-calling allows you to extend LLMs with custom capabilities by enabling them to form calls to external functions based on natural language instructions. Structured data extraction enables LLMs to pull usable information from unstructured text.
-Instructor bridges the gap between unstructured text and your Pydantic schemas, forcing models like Gemini, Claude, or GPT to return strict, type-safe Python objects instead of raw text.
-Instructor's most powerful feature is automated self-correction.
