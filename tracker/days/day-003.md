## What I learned

- `Field(...)` (Ellipsis) marks a Pydantic field as required with no default; `Field(None, ...)` or `Field(default=..., ...)` gives it a default and makes it optional
- `@field_validator` + `@classmethod` lets you run custom validation/sanitization *and* transform the value before it reaches route-handler code — validation isn't just pass/fail, it can also clean the data
- `@computed_field` adds a derived, presentation-only field to the serialized JSON response without storing it anywhere — kept business logic (e.g. "is this task urgent?") out of the database layer
- `response_model=` on a route decorator both documents *and* enforces the shape of what gets returned — it filters/validates the output, not just the docs
- `PUT` = full resource replacement (idempotent, client sends everything); `PATCH` = partial update (client sends only what changed) — and Python's `not in`, `del`, and the `global` keyword (needed because assigning to a name inside a function makes it local by default, unlike C# fields)
