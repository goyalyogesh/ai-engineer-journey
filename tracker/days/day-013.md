  Cleared up the misconception that embeddings get "decoded" back into text — they don't;
  the vector is just a search key, the real text is stored alongside it as metadata.

## What I learned

- 1536 is a fixed output size of the model, not a per-word count — same text, any length,
  same 1536 numbers.
- `(1536,)` vs `(1,1536)` — 1D flat vector vs. 2D "batch of 1" — different shapes for
  conceptually the same data.
- Cosine similarity measures *direction* (meaning), not magnitude — that's why it ignores
  text length.
- Embeddings are one-way/lossy — you can't reconstruct text from a vector. Retrieval works
  by storing text + embedding together and looking up by ID after a similarity match, not
  by decoding.
- Document homogeneity matters more than length — a long but single-topic doc embeds fine;
  a long multi-topic doc dilutes the signal. This is the real reason chunking exists.
