## What I learned

- Streamlit Cloud secrets don't land in real environment variables the way a local `.env` does — they're only reachable via `st.secrets`, so any code that reads `os.environ` directly (like `genai.Client()`) needs an explicit bridge line, or it fails in production even though it works perfectly locally. Same category of bug as the Day 4 `load_dotenv()` miss, just showing up at deploy time instead of at first run.
- Splitting business logic (`email_classifier.py`) from the UI framework (`app.py`) meant I could verify the actual LLM call worked correctly *before* debugging any Streamlit-specific rendering — isolated the two failure surfaces instead of debugging both at once.
- Instructor's `max_retries` isn't just a network-retry setting — on a validation failure (e.g. the model returns an urgency value outside the allowed `Literal` set) it feeds the exact Pydantic error back to the model as a follow-up message and asks it to self-correct, before ever returning control to my code.
- `@st.cache_resource` matters for anything that opens a connection (like the Gemini client) — Streamlit reruns the whole script top-to-bottom on every UI interaction, so without caching you'd reconnect on every single click.
